不背单词 · 复习体验优化与智能断点续学方案

版本 V1.0 · 2026.05 · 赵知涵 · 个人项目
1 产品背景与目标
不背单词以「真实语境学单词」为核心特色，凭借 150 万+原声例句、极简美学设计和科学的艾宾浩斯复习算法，在背单词 App 市场中建立了差异化优势。但在深度使用过程中发现，产品的核心竞争力集中在"新词学习"环节，而复习环节的体验设计相对薄弱，导致用户在中后期使用中出现明显的留存衰减。
产品优化目标：通过复习模式多样化与中断友好机制，降低用户在中后期的流失率，提升长期学习连续性，将不背单词从"学单词的好工具"升级为"帮用户坚持学单词的好伙伴"。
2 用户痛点分析
2.1 核心痛点一：复习模式单一枯燥
不背单词当前的复习流程为固定的「看例句→选词义」循环。该流程在新词学习阶段效果良好，但随着累积复习量增大，问题逐渐显现：
  • 机械疲劳：每次复习都是相同的交互范式，用户产生"肌肉记忆式"的点击惯性，而非真正的 recall 思考
  • 缺乏挑战感：没有变化和难度分层，"认识/模糊/不认识"的三档评价标准相对主观，用户容易麻木性地全部点"认识"
  • 缺少主动输出环节：当前流程都是"被动识别"（看到词→回忆词义），缺少"主动输出"（看到词义→回忆拼写/发音）的训练
2.2 核心痛点二：中断后单词堆积导致回归门槛高
艾宾浩斯遗忘曲线的副作用：中断 1-2 天后，待复习词量指数级增长。用户面对数百个待复习单词时产生强烈的"还债"挫败感，进一步加剧放弃意愿。
恶性循环：
中断1-2天 → 待复习词量从 30 暴涨至 200+ → 挫败感 → 更不想打开 App → 继续中断 → 待复习词量进一步堆积 → 最终弃用
该问题在不背单词中尤为突出，因其复习算法严格执行艾宾浩斯间隔，缺少对用户实际记忆留存情况的动态评估和柔性调节机制。
2.3 痛点优先级矩阵
编号痛点频率强度优先级
P1复习模式单一，产生机械疲劳每次复习高P0

3 目标用户
用户类型画像描述核心诉求
备考学生 四六级/考研/雅思备考生，每日固定时间背单词，词量需求大 复习效率最大化，用最少时间达到最好效果
自律较弱的学习者 有学英语的愿望但难以坚持，容易因忙碌/懒惰中断 降低回归门槛，给"重新开始"的勇气
长期英语爱好者 已养成背单词习惯，追求长期积累和牢固记忆 复习不枯燥，有挑战性和新鲜感
4 功能需求详述
4.1 F1：复习模式多样化
需求描述：在现有「看例句选词义」模式基础上，新增多种复习模式，用户可根据当前状态和个人偏好自由切换。
模式交互方式训练目标适用场景优先级
快速选择题卡 显示单词 → 4 个中文释义选项 → 限时 5 秒作答 快速 recall，强化词义关联 碎片时间、大量刷词 P0
沉浸式拼写 显示中文释义 + 发音 → 用户拼写单词 → 自动纠错 拼写能力，主动输出 专注学习时段 P0
听音辨义 播放原声例句音频（无文字）→ 选择对应的单词/释义 听力识别，语境理解 通勤/碎片时间 P1
看义拼词 显示中文释义 + 乱序字母 → 选择正确字母拼出单词 拼写 + 趣味性 轻松学习时段 P2
异常流程 / 边界场景
  • 快速选择题卡超时未作答 → 自动判为"不认识"，进入错题本；连续 3 题超时，提示用户是否需要切换回普通模式
  • 拼写模式输入近义词/同根词 → 提示"拼写正确吗？是否想写的是 [目标词]？"，避免因近义词混淆导致的挫败感
  • 听音辨义例句加载失败 → 自动跳过，不打断当前复习节奏
  • 当前词库内单词少于 5 个 → 隐藏对应模式，并提示"词库量太少，再学些新词试试"
4.2 F2：难度自适应复习策略
需求描述：根据用户对每个单词的历史掌握程度，动态调节该词在复习中出现的频率。已牢固掌握的词减少出现次数，将宝贵的时间分配给"快要忘记"的词。
算法逻辑：
每个单词的记忆强度评分 = f(最近一次正误, 历史正确次数, 连续正确次数, 距上次复习天数)
→ 评分高于阈值 → 复习间隔延长 2 倍
→ 评分低于阈值 → 复习间隔缩短 50%，优先出现在下次复习中
→ 连续 5 次正确且评分持续高于阈值 → 标记为"已掌握"，进入月度抽查队列
异常流程 / 边界场景
  • 用户连续点"不认识"同个词 → 当天不再重复推该词（避免挫败感），次日优先出现，并附带更多语境例句辅助理解
  • 用户手动标记"已掌握" → 尊重用户意愿，但不完全移除，30 天后进行一次抽查确认
  • 新词数量为 0 时 → 复习模式按钮淡化显示，引导用户先学习新词
4.3 F3：智能断点续学
需求描述：用户中断学习后再次打开 App 时，自动评估当前单词记忆留存情况，过滤已牢固掌握的词，将待复习量压缩至心理可承受范围，降低回归门槛。
核心机制：
Step 1 中断检测：检测到用户距离上次学习 > 48 小时 → 触发「智能断点续学」流程
Step 2 快速评估：从待复习词库中抽取 10% 样本词进行快速测试（用选择题卡模式），评估用户当前的记忆留存率
Step 3 智能筛选：基于评估结果，将待复习词分为三组：① 大概率已遗忘（强制复习）② 可能还记得（抽检测试）③ 大概率已掌握（跳过，放入月度抽查）
Step 4 压缩呈现：显示"检测到你已中断 X 天，已将待复习词量从 N 精简至 M"，降低用户的回归心理负担
异常流程 / 边界场景
  • 中断时间极短（< 24 小时） → 不触发断点续学，正常显示待复习量
  • 用户拒绝评估 → 提供"直接全部复习"的入口，尊重用户选择
  • 评估结果中留存率极低（< 30%） → 提示用户是否需要降低新词学习量，优先巩固旧词
  • 评估过程中退出 → 保存已评估部分的进度，下次进入时支持续接或重新评估
  • 用户已连续学习多日（未中断） → 该功能入口不可见，避免干扰正常流程
5 核心用户流程
5.1 场景 A：正常复习流程
首页 → 点击「Review」按钮 → 显示复习模式选择面板 → 用户选择模式（如"快速选择题卡"） → 进入对应模式复习 → 每完成 10 词展示一次小进度总结 → 全部完成后展示本次复习报告（正确率 / 用时 / 薄弱词） → 返回首页
5.2 场景 B：中断后回归流程
中断 3 天后打开 App → 首页显示待复习 127 词，同时弹出「智能断点续学」卡片 → 用户点击"一键精简" → 系统进行快速评估（约 30 秒完成） → 评估完成后展示精简结果：127 → 45 → 用户以 45 词的合理量开始复习 → 复习结束后展示"欢迎回来"总结 vs 如果用户选择"不精简" → 显示全部 127 词，但标注推荐优先级
